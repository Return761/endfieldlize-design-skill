# Design evaluation

Start with a representative task, the actual rendered app, seeded data, and the viewport and states that matter. Exercise the happy path, a failure or empty state, and a narrow viewport. Check whether actions are discoverable and feedback preserves context. Test keyboard reachability and focus when possible.

Inspect captured results for content hierarchy, spacing, overflow, alignment, legibility, and effective task organization. If a design looks templated, identify the specific layout or interaction that distorts the real objects and propose a change tied to the task. Compare screenshot revisions at the same dimensions and state. Make one prioritized correction and rerun the relevant check.

Use [evidence rubric](references/evidence.md) to record results and reproduce checks. Mark checks unavailable when runtime, browser or media support is missing. Use local build and schema checks where available and retain manual assertions as pending until observed.
