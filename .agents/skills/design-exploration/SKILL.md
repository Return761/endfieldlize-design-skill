# Design exploration

For a bounded request with an established workflow, trace the affected task, state and regression risk, then implement directly. For open-ended design, identify the user's jobs, representative data and the relationships that determine the cost of an operation. Use realistic examples with branches, missing data, long names and conflicting states.

Keep candidate directions independent until you can compare the same difficult task across them. For a novel interaction, explore three viable models where scope permits. Change the organizing object, how a user reaches it, or how the user acts on it. Consider graph, tree, spatial, temporal, semantic and object-centered models when they reveal different operations. Invent new primitives when they shorten or clarify a concrete task.

Record each candidate's selection, navigation, state transitions, complex walkthrough, accessibility path and failure mode. Compare task cost, context preservation, discoverability and scale. Combine candidates only when the combined model has a clear primary path and a shared identity model. Explain the selection and the evidence that would change it.

Read [exploration worksheet](references/method.md) for prompts and the `InteractionSpec` handoff. Bring the selected behavior into the existing target stack. Use graphic-composition for visual grammar and design-evaluation for verification when available.
